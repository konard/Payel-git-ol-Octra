Раз теперь мы отходим от концепции единорога и иерархической системы и просто 
предоставляем удобный хостинг без заморочек и ssh то нужно менять архитектуру самого приложения
например оркестратор больше не нужен как и agent да и в целом теперь можно отойти к монолитной архитектуре
потому что в микросервисах больше нету никого смысла только усложнение 

Ключевые задачи которые нужно покрыть:
- Размещение агентов
- Хранение пользователей
- Хранение данных и состояния о пользовательских агентах 
- Хранение статистики 

Стек остаётся Go:
- Go
- fasthttp (HTTP)
- GORM (ORM)
- pgx / postgres
- go-redis
- Nix (CLI окружения)

База: PostgreSQL + Redis для кэша

Что нужно убрать:
- Сервисы:
  - user сервис
  - agents сервис
  - orchestrator
  - apigateway
- Излешние наложения:
  - промты (босса, менеджера, воркера)
  - промты при отправке сообщений ии

Что не трогать:
- poster
- tgbot
- frontend
